# 앵커 수집 주의사항 (인벤토리 워크플로 산출)

[kAxis] (1) 용량 다점 사다리(K=1/5/20/60)는 legacy8-A8-TAG에만 존재(구코드 30번 + 신코드 33번 재현, 독립 2계열 — probit 적합 시 코드 계열을 공변량 또는 별도 플랫폼으로 취급 권장). K20/K50/A12/CFR 플랫폼은 K=5 단일 용량 + K=0(off)뿐이라 K축 곡선 적합 불가, 임계 이동 검증용 1점 앵커로만 사용 가능. (2) 구코드 레거시 런 폴더(30_vic_potfrac_seedsweep, 28_ablation_vic_2m_clean)의 eval_results.csv는 200게임 체크포인트 곡선이며 100k×5 원자료 CSV가 아님 — per-seed 정밀값은 results/_logs/night_e3e_*·night_e7e_* 평가 로그에서 추출해 실험일지와 대조(전부 일치). 단 레거시 off(0/6)와 seed42 clean 런들(single/cycle/mixed on·off)은 해당 정밀 로그를 특정하지 못해 실험일지 기록값 그대로 사용(원자료 미확인 표시). (3) n_positive 정의 = per-seed 평균(각 seed 100k게임×5회 반복의 평균 mbb/g)이 양수인 seed 수 — 일지·README 관행과 동일. (4) SD 불일치 2건: 32/k20 fixed5 README ±467 vs 원자료 표본SD 494.7, k50_a12 off ±175 vs 179.8 — 평균은 전부 일치, SD 산출 방식 차이로 추정, 원자료 우선. (5) 제외 런: rand_fixed1·rand_off(33번)와 28c rand_on/off — 학습상대=Random이라 vsRand가 ID가 되어 OOD 회복 probit 앵커로 부적합. 16·17·18·19·21b·21c·24번(CHECK=1chip=K=1 상당) — clean 이전 누수(올체크 균등분배 폴백) 시대 코드 + 대부분 seed42 단일이라 clean 규약 앵커와 혼합 금지(28번 비-clean 요약의 single on +987도 누수 산물로 제외, clean 재현 시 -375.6). (6) K=0 행은 fixed 런이 아니라 VIC off 기준선을 용량 0 앵커로 포함한 것 — 적합에서 빼려면 제거 가능. (7) CFR 플랫폼의 vsRand는 홀드아웃(학습상대=CFR)이고 TAG 플랫폼의 vsRand도 홀드아웃(학습상대=TAG)이나 학습 분포가 다르므로 플랫폼 효과에 학습상대 차이가 포함됨. (8) 33번 재현의 fixed20/60 4/5는 레거시 5/5와 편차(README 정직 기록) — 고K 안정성 주장에 인용 주의.

[aAxis] (1) 원자료 소재: 30_vic_potfrac_2m·30_vic_potfrac_seedsweep 폴더 내 eval_results.csv는 200게임 체크포인트 로그(잡음 지배)이며, 100k×5 정밀치는 CSV로 존재하지 않고 results/_logs/의 로그 파일(peval_*=seed42 α-곡선, night_e5e_*=chec a4/a8/a15 sweep, sse_*=나머지 sweep)에만 '==> <run> vsRand mean' 형태로 기록되어 있다. 이 로그가 사실상의 원자료이고, 병합 6-seed 값이 실험일지 2385행의 전 수치(+223/+888/+1235/+1546/-318 등)와 일치함을 산술 재계산으로 확인했다. 32·33번은 precision_eval.csv(rep 0-4 = 100k×5)가 원자료라 CSV에서 직접 계산. (2) n=1 앵커(α=1/2/6/25%의 seed42 단독, terminal a8·a15 포함)는 E7이 실증한 단일-seed 부호요동 위험이 있으므로 probit 적합 시 n=1 가중을 낮추거나 제외 검토 필요 — 특히 terminal a15 -336.5는 양쪽 이웃(+421/+452)과 부호가 다른 단독 dip. (3) '전이구간 α 8~15% 요동'의 실측 근거는 두 곳: legacy8 prev코드 chec 사다리의 비단조 양수율(a8 3/6 → a10 1/6 → a15 2/6 → a20 5/6, night_e5e/sse 로그)과 ladder 재현 배치(a08 2/5 → a10 2/5 → a15 3/5 → a20 4/5, 33_ladder_replicate_k8 CSV). E9(실험일지 2431행)의 α_min 중앙값 14.8%·'관측 전이 8~20%'는 이 실측과 정합하나 E9 자체는 학습 Q 기반 대리 추정(부분 in-sample)이므로 probit의 독립 검증이 아니라 대조군으로만 써야 한다. (4) α=0(off) 앵커는 checktime/terminal 공통이며 K축의 K=0과 동일 런이다 — 두 축 데이터를 합칠 때 중복 계상 주의. 본 목록에는 axis=alpha-checktime에 1회씩만 실었다. (5) terminal 모드는 α≥0.35 plateau가 5-seed로 확보됐지만 checktime은 α=0.30 초과 실측이 legacy-prev에 없다(ladder 재현의 chec_a50만 존재). (6) CFR 플랫폼의 vsRand는 상대(Random)는 동일하나 학습 분포가 TAG와 달라 별도 플랫폼으로 표기했고, 해당 플랫폼에서 vsRand 회복이 곧 전면 회복이 아님(vsCFR·vsLAG·vsMAN 음수)을 주의. (7) seedsweep의 chec_a30 변형 런(allcheck_only/invested_only/mixed/cycle)은 α 용량이 아닌 적용범위·학습상대 변형이라 α축 앵커에서 제외했다. (8) night_e2_*(a30·off 학습 로그)에는 vsRand 100k×5가 없고 후속 페르소나 스펙트럼 평가만 append되어 있다 — a30·off의 100k×5 원천은 sse_* 로그 단일이므로 문서 간 수치 충돌은 없었다.
